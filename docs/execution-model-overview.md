# AstaPS 重构：现行决策与实施路线

> 2026-11-11。唯一现行摘要；具体论证见本文件压缩前的 Git 历史。当前分支 `rino/refactor/jline4-shell`，已合并上游 `MeChen618/AstaPS/main@a49f51a`（7.2 WIP）。**本文中的“已决定”是业务/架构决议，不表示代码已实现**。历史 7.1 源码记录不能当作当前 7.2 实现。

## 1. 全局架构（已决定）

- **A / M2**：逐步重构整个服务端；允许 Gradle 工程多模块，具体模块清单、接口、独立产物数量未定。首批 CLI、Inventory，后续 Quest、World。
- **D1**：保留 `HYBRID` / `GAME_ONLY` / `DISPATCH_ONLY`，Game、Dispatch 可分别或同进程运行；模块边界与进程边界分别决定。
- **E1 / K1**：协议、CLI、Web、插件通过所属业务能力修改状态；原版核心玩法内置，第三方插件可扩展。拒绝无收益的旧 API/旧存档兼容层。
- **R2**：一个 UID 的个人状态（Inventory、Quest、成长、装备关系、个人 Tick）逻辑串行，不同 UID 可并行。
- **S2**：同一 World 的 Scene、实体、Lua、战斗事件、Tick 串行，不同 World 可并行。`AttackResult` 目标处理、伤害应用、HP/死亡归 S2；保留 `UnionCmd` 内 Ability/攻击顺序；个人副作用交 R2。跨域异步不互等，UID/World 不独占线程。
- **B1 / C1**：Avatar/R2 管等级、装备、天赋等原始数据；**不缓存派生属性**。World/S2 经 EntityAvatar 直接读 Avatar，需要属性时结合武器、圣遗物、等级、Buff 按需计算，无属性副本。一次计算原始读取须一致，不能同步阻塞跨域，具体机制待定。S2 管 `hp`、`energy`、Buff、护盾；Ability 变更仍需跨域交接。C1 保留客户端主要伤害输入，由 World 校验应用；**不强制每次攻击重算全属性**；C2 未批准。
- **持久化 P1**：个人业务内存变更在 R2 中完整同步完成；一个 UID 一条逻辑有序的异步 DB 写入线，不同 UID 可并行。经济操作必须先取得该次操作全部写入准入，否则在修改前拒绝；不允许拥塞时退化为调用线程直接写 DB。写入失败可观察，重登录读取不能越过旧会话尚未完成的持久化。奖励回执 `PREPARED` 的必要同步确认保留。装备内存成功即可响应，无需等待普通 MongoDB 写入，不保证崩溃时跨文档原子性。

## 2. CLI / 命令（已决定）

- Java **21** 不动，Java 25 长期目标；引入完整 **JLine 4 Shell**（最新核查候选 4.5.0），Picocli 用于业务参数；Shell 的内置能力开放范围尚未决定。
- **P01A**：保留 `Player sender`；受信任服务器控制台 `sender=null`，Web 验证管理会话后具有控制台权限；不建额外管理员身份体系。
- **目标**：显式选择器只用 `@UID`、`username@`（唯一账号用户名）；单条显式选择不改变默认目标。游戏玩家默认自己；本地 Shell、每个 Web 管理会话各自保存目标；无参 `target` 恢复执行者（控制台为无目标），玩家下线清除绑定。可临时给一批命令设置目标（T03B），语法未定。
- **权限**：玩家可绑定别人，但跨 UID 操作要求基础权限及 `.others` 权限；用稳定 UID 判断本人。权限和参数都错时先报权限错误（X02B）。插件更改目标后重新授权。
- **F1**：前台 Shell 在外部交互线程等待**实际业务完成**，按真实成功/失败驱动 `&&`、`||`；普通异步 DB 落盘不属于完成屏障。游戏/World/UID 业务线程不允许阻塞等待；输出过滤不改变业务结果。

## 3. Give（已决定）

- 语法 `give [@UID|username@] item [count] [类型专用命名选项]`；item 仅数字 ID 或合法内部资源 ID；数量为十进制正整数，默认 1，只对在线且有效会话玩家生效。删除 `-n/--amount`、尾置选择器、`all/weapons/mats/materials/avatars/characters` 批量类别。
- **G04C**：按真实剩余容量截断，实发 0 也是成功且明确报告无变更；参数、权限、离线目标、入库失败为失败。材料按 `stackLimit`/槽位、装备按装备槽位、货币/经验/即时效果按各自业务容量；没有额外单次 give 上限。
- 武器默认 1 级、精炼 1；圣遗物默认 +0，显式等级按显示等级验证；角色默认 1 级、0 命、三个天赋各 1。已有角色只改显式属性；重复获得且无属性变更则成功且不修改。
- 附加属性只用**大小写敏感、kebab-case、长选项**；具体英文参数名未定。非法范围报错。角色统一天赋等级被单项等级覆盖；等级可推导突破，也可显式指定突破，二者冲突时以突破限制为准；仅指定突破时可升/降等级到合法范围。
- 支持按资源 ID 发完整圣遗物套装；数量按套数，空间不足时优先尽量多的完整套，再发部分套，允许不完整并报告数量；主、副词条由专属构造逻辑验证，缺省合法随机生成，显式值的细则未定。给角色、装备、材料、货币、一次性解锁需遵从各自业务规则。

## 4. 物品、装备与 TPS（已决定）

- 统一公共接口 **`InventoryItem`**，最小 `getItemId():int`、`getGuid():long`；武器、圣遗物、每 itemId 一份可变材料堆叠纳入。余额、角色与一次性效果不默认纳入。
- **身份**：运行时 GUID 在 Inventory 接收入库时分配，由实例持有，只对当前登录有效，重登录重分配；持久记录使用 MongoDB `ObjectId`，不用 GUID 作持久引用。
- **职责 B**：武器、圣遗物、任务、奖励等业务系统主导自身规则；Inventory 管持有、容量、堆叠、入库、消费与删除。武器/圣遗物各有类型专属构造逻辑，不为迁移旧 `GameItem` 默认增加兼容层。
- **装备 A/A1**：普通装备物品持久记录被哪个角色装备；同 UID 内存变更整体同步、写入异步有序，解除旧关系先于写新关系。角色运行时槽位映射可据此建立；不额外要求 MongoDB 跨文档事务。
- **TPS T1**：保留专有有序多武器装载；正常角色 `Avatar.tpsWeaponIds`、临时角色 `Player.tpsLoadout` 为关系权威；InventoryItem 负责 TPS 武器持有，TPS 系统负责跨角色唯一性与临时恢复。试用装备、场景掉落的生命周期与库存持有分开。
- **Remove / Consume**：按目标状态清理的 Remove 幂等（已不存在即成功）；定量扣除用 Consume 类语义，数量不足可拒绝。具体 API 名称及 Quest 旧调用分类未定。

## 5. Quest / World 协作（已决定）

- **Q1**：Quest 成功包含所属 UID 的任务状态、即时个人 FinishExec 真实执行成功、约定奖励本次尝试完成；独立 World/Scene/Lua 后置效果不在成功屏障内。
- **QR3**：奖励允许部分发放并完成 Quest；不强制回滚、不做欠账补发。全部被拒、奖励缺失、use-on-gain 失败的业务解释尚未定。
- **X1 / S-F**：所有即时个人 FinishExec 必须实际成功；第一个失败立即停止本次后续即时个人 Exec，Shell 返回失败。**已发生状态/副作用保留**，不回滚、不补偿、不自动重试；不自动套用到 BeginExec、FailExec 或独立 World 后置动作。
- **W-H**：多人 World 共享 Scene 的 Quest group suite/剧情阶段由当前房主权威决定，访客不能用个人任务覆盖房主 Scene；个人任务与库存仍归本人。
- **G-C**：确实依赖 World 结果的混合 Exec：R2 发起 → S2 实际执行并返回成功 → R2 更新依赖的个人记录 → 确认成功。任务已排队、脚本回调已注册均不算完成；World 失败不得先写 UID 成功记录。双方执行域不阻塞互等。

## 6. 证据、待定与实施

- **证据原则**：先查原版 `RinoPaw/Genshin-Reverse` 对应 EXE/metadata/资源，再核对最新 `MeChen618/AstaPS/main` 源码和当前 fork；原版客户端数据不能证明官方服务端线程/事务语义。参考 Grasscutter、LunarCore、Folia 的具体实现，保留各自适用边界。
- **当前上游差距**：7.2 仍是 JLine 3.30.14 + Picocli 4.7.7，`CommandMap.invoke():void` 丢失退出码、控制台/Web 共用目标、异步文本捕获不足；JLine 4.5.0 默认 Dispatcher 对正常返回的整数仍写退出码 0。Quest 与 GameServer Tick 也尚无 R2/S2 统一执行权。7.2 协议仍有未映射项，不能把它们当成 CLI 本地解析的阻塞。
- **B1 核查**：当前 `EntityAvatar` 共享 `Avatar` 可变属性 Map，`recalcStats()` 清空重建且刷新 Ability/通知。迁移须拆分纯属性计算、Ability 状态更新、属性封包，并覆盖队内外角色及 HP/能量恢复。
- **主要未决**：Shell 完整功能、JLine/Picocli 结合与退出码技术、Web 并发/超时/会话生命周期；R2/S2 具体调度和跨域回执；B1 的并发一致读取和动态效果；M2 模块清单；Give 属性选项细则；Quest 访客进度与冲突优先级；旧 World 已成功但 UID 提交前换 World/Scene/会话的回执规则 **V-S（严格当前上下文）/V-H（接受已证实历史）**。**不能自行批准这些影响业务行为的选项**。
- **实施次序**：A. 无副作用 Shell 实验：交互、补全、`&&/||` 真正反映失败；B. `give` 跑通目标/权限→R2→Inventory→P1→F1；C. Web/游戏入口复用同一结果，再推进 Quest 和 World Tick。先小范围验证，不在研究阶段为 CI 付费；**交用户测试或提交上游前必须跑相关 CI**。不擅自建分支，保留现有上游基线。
